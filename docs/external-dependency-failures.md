# 存储连通性

设计、开发、测试和 review 按实际 backend 考虑源端／目标端存储在连接建立、列举、读取、写入、提交和关闭期间的连接失败、中断、静默丢包及请求超时。ClickHouse、产品 callback 和迁移代次策略由使用本库的应用负责。

- **准确分类**：backend 保留底层结构化原因、操作阶段、取消及已发送但结果未知等证据，准确映射 StorageError；认证／权限等明确非网络错误不能被归为断网重试。
- **预算归属**：client 负责协议安全范围内的短时恢复，backend 仅保留本操作必要的安全恢复与错误映射，通用调度执行调用方指定的预算和取消策略；明确次数、退避和整体截止时间，避免多层重试叠加。
- **扫描与普通操作**：普通 backend 接口不隐式携带产品扫描策略。调用方指定识别故障后约 3 秒的窗口时，由通用调度层统一执行，根验证、分页和并发恢复不能重置同一次故障的截止时间；拷贝与写入等另行确定策略。静默丢包检测耗时另计并约束。
- **结果与收尾**：连接恢复不能证明句柄、游标或操作状态仍有效；按协议证据和幂等性决定重放，保留未知写结果。等待、退避、背压和在途请求均须响应取消，明确部分写入、临时对象、句柄及后台任务的所有权和收尾结果。

## 真实故障注入

新增或修改存储访问、连接、超时、重试、取消及恢复逻辑，必须在受影响真实 backend／协议链路实施受控故障注入，按场景覆盖闪断、持续断连、静默丢包／超时及恢复。确定性测试验证预算和边界，不能替代真实链路验收。

验证错误分类、检测与恢复／退出耗时、故障期间取消、最终数据、恢复计数及资源收尾，并记录正常性能／内存开销。报告注入对象与方式、实际结果、未测环境、跳过项和能力限制；遵守测试环境允许范围及清理约束。

本页是设计与验收要求，不代表各 backend 已完成对应实现或实测。
