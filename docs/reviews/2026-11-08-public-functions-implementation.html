验证

本地 CI 各阶段通过：data-mover 的架构守卫、harness、独立 feature 矩阵、严格 all-targets Clippy（零警告）、workspace／文档测试（2,428 passed、53 ignored）、examples 和 e2e-local；terrasync 的 fmt、workspace all-targets check／Clippy、workspace（633 passed、121 ignored）和串行远端进程 E2E（16 passed）。terrasync Clippy 仍有既有告警；ignored 为默认套件未运行项，不能视为相应实机验收通过。

  • 现有普通／历史观察测试 18 项，过滤相关测试 280 项，HDFS crate 测试 105 项通过。
  • 路径读取确定性测试 8 项通过，包括仅 stat 不访问 metadata，以及 stat／属性共享恢复窗口、取消和准确 NotFound。
  • 元数据引擎测试 64 项通过，新增组合验证证明“历史版本存在”不能替代“当前发布版本未变化”的约束。
  • 隔离 RustFS：属性观察 9 种、stat 7 种、历史元数据应用 7 种场景通过，覆盖权限拒绝、断连、静默超时、取消、闪断恢复和适用的提交响应丢失。
  • 独立 S3 检查确认观察无数据 GET／写入、全部源版本与哨兵保留；历史 tags 写入不创建数据版本，当前版本和内容不变，不发出数据 GET／PUT。测试容器已清理。

架构审查结论

路径观察与恢复机制仍集中在 storage-core，版本选择和元数据计划执行仍由原引擎负责。terrasync 只传计划与选择并消费有类型的结果，不增加 backend 分支、协议重试或新的恢复循环。观察继续使用 Arc 共享历史；无计划的路径读取不新增属性接口调用，旧发布校验路径不新增 HEAD。检查覆盖职责归属、重复入口删除和调用方迁移。

后续事项与人工确认

Expert 构造合并尚未实施：拟在原 new 上接收选择枚举 Current／Observed { version_index }，保留“当前对象变化检查”和“固定扫描捕获版本”的不同语义。现有 SourceVersion 无法表达观察索引；新增公开选择类型正在等待人工明确确认，依据 AGENTS.md。

  • ReadSource 的 describe／describe_version，以及 Metadata 角色层的 apply／apply_to_version 仍待收敛，需同步所有 adapter、wrapper 与测试，并保证不支持历史版本时先拒绝、无当前对象副作用。
  • QoS 构造统一与两套准入账本合并尚未实施；后者须作为独立行为修复验证，不能只修改名称。
  • 校验期间在途 IO 的取消缺口仍待独立修复；本批没有宣称已完成统一网络故障控制。
  • 其余条件性合并及可见性建议仍以原审查文档为准。确需新公开请求／模式／入口时先人工确认。

性能与未测范围

本批通过结构和请求计数确认旧路径未增加数据读取、属性读取或历史克隆，没有执行迁移吞吐／峰值 RSS 的正式同环境 A/B，因此不能据此声称已达到全量 5% 损失目标。本地工具链为 rustc 1.98.1；没有另行复跑 CI 固定的 Rust 1.95。真实故障只复测了上述隔离 S3 链路；Windows 和本批 NFS／CIFS／HDFS 真实服务未测。HDFS 的 105 项为自动测试，不是实机 HA 验收。
