## Contracts to preserve during extension

`verify_published` checks current head; `verify_version` permits history (`verify.rs:100,108`). Extend the old verifier with a read selector and independent head constraint to merge both. Point reads can likewise merge through an optional observation plan and discriminated outcome, preserving stat-only cost. Concrete proposals are in `functions-storage-metadata.md`. `read_current_range` adds fresh capture, pinning, exact EOF and ordered offsets (`read_range.rs:35–95`); extending raw reads can absorb these with broader adapter/output changes. Protected purge, persistence, owned Direct cleanup and metadata-failure/data-completion facts also need explicit semantics. Existing delete/publish/strict metadata APIs cannot substitute unchanged; semantic differences alone do not require parallel entry points.

Supporting semantic gap: new metadata verification awaits stat/describe/metadata without cancellation selection (`verify.rs:86–99,123–127,179–204`), contrary to `docs/external-dependency-failures.md:8`; an empty plan can return success after cancellation (141–142).
